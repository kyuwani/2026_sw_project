# DevLog 제품 정의서

## 1. 문서 목적

이 문서는 DevLog가 해결하려는 문제와 대상 사용자, MVP 범위 및 제품의 발전 방향을 정의한다. 기능 구현 중 범위나 우선순위가 모호할 때 이 문서를 제품 판단의 기준으로 사용한다.

## 2. 서비스 목적

DevLog는 개발자가 프로젝트, 할 일, 학습 기록, 기술 스택, GitHub 활동을 한곳에서 관리하고 자신의 성장 흐름을 확인할 수 있는 개인 개발자 대시보드다.

개발 학습과 프로젝트 작업은 여러 도구에 흩어지기 쉽다. DevLog는 다음 문제를 해결한다.

- 진행 중인 프로젝트와 다음 작업을 한눈에 파악하기 어렵다.
- 무엇을 얼마나 학습했는지 꾸준히 기록하기 어렵다.
- Task 완료와 학습 시간이 실제 성장으로 어떻게 이어지는지 확인하기 어렵다.
- 프로젝트와 GitHub 저장소의 관계를 별도로 관리해야 한다.
- 취업 준비나 회고 시 과거 활동을 다시 정리하는 데 시간이 많이 든다.

DevLog의 핵심 가치는 **기록**, **실행**, **회고**다.

1. 기록: 프로젝트와 학습 활동을 빠르게 남긴다.
2. 실행: 우선순위와 마감일을 통해 다음 행동을 결정한다.
3. 회고: 누적 데이터를 시각화하여 성장 패턴을 확인한다.

## 3. 주요 사용자

### 3.1 개발을 공부하는 대학생

- 수업, 알고리즘, 개인 학습 기록을 함께 관리한다.
- 팀 또는 개인 프로젝트의 Task와 일정을 정리한다.
- 포트폴리오 작성 전에 학습과 개발 이력을 되돌아본다.

### 3.2 취업 준비생

- 여러 포트폴리오 프로젝트의 진행 상태를 관리한다.
- 기술별 학습량과 꾸준함을 확인한다.
- GitHub 저장소와 프로젝트 설명을 연결해 관리한다.

### 3.3 주니어 개발자

- 업무 외 개인 프로젝트와 학습 계획을 관리한다.
- 주간·월간 학습 시간을 회고한다.
- 부족한 기술 영역을 파악한다.

### 3.4 개인 프로젝트를 관리하는 개발자

- 아이디어부터 완료까지 프로젝트 상태를 관리한다.
- 프로젝트를 실행 가능한 Task로 나눈다.
- 저장소와 최근 개발 활동을 한곳에서 확인한다.

## 4. 핵심 기능

### 4.1 사용자 인증

- 이메일과 비밀번호를 이용한 회원가입 및 로그인
- GitHub OAuth 로그인과 계정 연결
- 로그아웃
- 인증이 필요한 화면 보호
- 사용자별 데이터 격리

### 4.2 Dashboard

- 진행 중·완료 프로젝트 수
- 완료 Task 수와 완료율
- 최근 학습 기록
- 연속 학습 일수
- 프로젝트별 진행률
- 최근 활동
- 주간 성장 요약

### 4.3 Project

- 프로젝트 생성, 조회, 수정, 삭제
- 계획, 진행 중, 일시 중지, 완료, 보관 상태 관리
- 시작일과 종료일 관리
- 설명과 기술 스택 관리
- GitHub Repository 연결
- Task 완료율 기반 진행률 표시

### 4.4 Task

- 프로젝트별 Task 생성, 조회, 수정, 삭제
- 할 일, 진행 중, 완료 상태 관리
- 우선순위와 마감일 관리
- 상태, 우선순위, 마감 여부 필터링
- 완료 시각 기록

### 4.5 Learning Log

- 날짜별 학습 내용 기록
- 학습 시간 기록
- 카테고리와 기술 스택 지정
- 기간, 카테고리, 기술 스택 검색 및 필터링
- 기록 수정과 삭제

### 4.6 Analytics

- 주간·월간 학습 시간
- Task 완료율
- 프로젝트별 진행률
- 기술별 학습 비율
- 연속 학습 일수

### 4.7 GitHub

- GitHub 계정 연결
- 본인 Repository 목록 조회
- 프로젝트와 Repository 연결
- 연결된 Repository의 기본 정보와 최근 Commit 조회

### 4.8 Profile

- 이름, 프로필 이미지, 자기소개
- GitHub 링크
- 주 사용 기술
- 사용자 시간대

## 5. 주요 사용자 플로우

### 5.1 첫 사용

1. 사용자가 이메일로 가입하거나 GitHub로 로그인한다.
2. 이름, 자기소개, 시간대와 주 사용 기술을 입력한다.
3. 첫 프로젝트를 생성하거나 학습 기록을 작성한다.
4. Dashboard에서 생성된 요약 정보를 확인한다.

### 5.2 프로젝트 관리

1. 사용자가 프로젝트 이름, 설명, 일정, 상태, 기술 스택을 입력한다.
2. 프로젝트를 실행 가능한 Task로 나눈다.
3. Task의 우선순위와 마감일을 지정한다.
4. 작업하면서 Task 상태를 변경한다.
5. DevLog가 완료 Task를 기준으로 프로젝트 진행률을 계산한다.
6. 프로젝트 완료 후 기록을 회고한다.

### 5.3 학습 기록

1. 사용자가 오늘 학습한 내용과 시간을 기록한다.
2. 카테고리와 관련 기술을 선택한다.
3. Dashboard에서 최근 기록과 연속 학습 일수를 확인한다.
4. Analytics에서 주간·월간 학습량과 기술별 비율을 확인한다.

### 5.4 GitHub 연결

1. 사용자가 GitHub OAuth로 계정을 연결한다.
2. 권한 범위 내 Repository 목록을 불러온다.
3. DevLog 프로젝트에 Repository 하나를 연결한다.
4. 프로젝트 상세 화면에서 Repository 정보와 최근 Commit을 확인한다.

## 6. MVP 범위

### 6.1 반드시 포함한다

| 영역 | MVP 기능 |
| --- | --- |
| 인증 | 이메일 회원가입·로그인·로그아웃, GitHub OAuth, 보호된 화면 |
| Dashboard | 핵심 지표, 최근 프로젝트·Task·학습 기록, 연속 학습 일수 |
| Project | CRUD, 상태, 기간, 설명, 기술 스택, 진행률 |
| Task | CRUD, 상태, 우선순위, 마감일, 기본 필터 |
| Learning Log | CRUD, 학습 시간, 날짜, 카테고리, 기술 스택, 검색·필터 |
| Analytics | 주간·월간 학습 시간, Task 완료율, 기술 비율, 연속 일수 |
| GitHub | OAuth 연결, Repository 선택, 최근 Commit 조회 |
| Profile | 이름, 이미지, 자기소개, GitHub 링크, 사용 기술, 시간대 |
| 품질 | 반응형 UI, 기본 접근성, 입력 검증, 인가, 핵심 테스트 |

### 6.2 MVP에서 제외한다

- 팀 프로젝트와 멤버 초대
- 실시간 공동 편집
- 댓글, 멘션, 알림
- 공개 프로필 및 소셜 피드
- 모바일 네이티브 앱
- AI 자동 회고 및 추천
- 캘린더·Notion·Slack 등 외부 서비스 연동
- GitHub Webhook을 이용한 실시간 활동 저장
- 파일 첨부 및 프로젝트 갤러리
- 세밀한 역할 기반 권한 관리
- 다국어 지원

## 7. 제품 정책

### 7.1 프로젝트 진행률

- 기본 진행률은 `완료 Task 수 / 전체 Task 수 × 100`으로 계산한다.
- Task가 없으면 진행률은 0%다.
- MVP에서는 수동 진행률 입력을 제공하지 않는다.

### 7.2 연속 학습 일수

- 사용자의 설정 시간대를 기준으로 날짜를 판단한다.
- 해당 날짜에 학습 시간이 1분 이상인 기록이 있으면 학습일로 인정한다.
- 오늘 기록이 없고 어제까지 연속 기록이 있으면 어제를 기준으로 현재 연속 일수를 계산한다.

### 7.3 데이터 소유권

- 모든 프로젝트와 학습 기록은 개인 소유다.
- 사용자는 자신이 소유한 데이터만 조회하거나 변경할 수 있다.
- MVP에서는 데이터 공개 기능을 제공하지 않는다.

### 7.4 삭제

- 사용자가 확인 절차를 거쳐 직접 삭제한다.
- 프로젝트 삭제 시 하위 Task와 기술 연결 정보도 함께 삭제한다.
- 계정 삭제와 복구 정책은 정식 출시 전에 별도로 확정한다.

## 8. 비기능 요구사항

- 모바일, 태블릿, 데스크톱에서 핵심 기능을 사용할 수 있어야 한다.
- 키보드만으로 주요 폼과 내비게이션을 사용할 수 있어야 한다.
- 색상만으로 상태를 구분하지 않는다.
- 외부 입력은 Zod로 검증한다.
- 인증과 리소스 소유권 확인은 서버에서 수행한다.
- Secret과 OAuth 토큰을 클라이언트에 노출하지 않는다.
- 일반적인 Dashboard 조회는 체감상 지연이 크지 않아야 한다.
- 오류, 빈 상태, 로딩 상태를 각 주요 화면에서 제공한다.

## 9. MVP 완료 기준

다음 조건을 모두 만족하면 MVP 기능 개발이 완료된 것으로 본다.

- 신규 사용자가 가입하고 로그인할 수 있다.
- 사용자가 프로젝트와 Task를 생성하고 완료 처리할 수 있다.
- 사용자가 학습 기록을 작성하고 검색할 수 있다.
- Dashboard와 Analytics가 실제 사용자 데이터를 올바르게 집계한다.
- 사용자가 GitHub 계정을 연결하고 Repository와 최근 Commit을 조회할 수 있다.
- 다른 사용자의 리소스에 접근할 수 없다.
- 핵심 흐름이 모바일과 데스크톱에서 동작한다.
- 핵심 비즈니스 규칙 테스트와 주요 E2E 시나리오가 통과한다.
- lint, typecheck, test, build가 통과한다.

## 10. MVP 이후 확장

### 10.1 구현 완료

- 캘린더 기반 최근 365일 학습 히트맵
- 이전 동일 기간과 비교하는 주간·월간 자동 회고 리포트

### 10.2 확장 후보

- 공개 개발자 프로필과 포트폴리오 공유
- 프로젝트 팀원과 역할 관리
- AI 기반 학습 요약과 다음 학습 추천
- GitHub Webhook 기반 Commit·Pull Request 활동 동기화
- 목표 설정과 리마인더
- 데이터 내보내기와 가져오기
- Notion, Jira, Linear, Slack 연동
- PWA 및 모바일 알림
- 프로젝트 템플릿과 반복 Task

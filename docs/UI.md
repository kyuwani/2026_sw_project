# DevLog UI 설계

## 1. 문서 목적

이 문서는 DevLog MVP의 화면 구조, 반응형 동작, 공통 컴포넌트 및 페이지별 정보 계층을 정의한다. 시각 디자인 상세보다 사용자가 빠르게 현재 상태를 이해하고 다음 행동을 수행하는 것을 우선한다.

## 2. 디자인 원칙

- 핵심 행동은 한 화면에서 쉽게 찾을 수 있어야 한다.
- 상태와 수치는 카드 수를 과도하게 늘리지 않고 계층적으로 표현한다.
- 빈 상태는 다음 행동으로 연결되는 안내를 제공한다.
- 로딩, 성공, 오류 피드백을 명확히 제공한다.
- 색상만으로 상태나 우선순위를 전달하지 않는다.
- 모바일에서도 프로젝트와 학습 기록 작성이 가능해야 한다.
- 파괴적인 작업은 확인 절차와 명확한 문구를 제공한다.

### 2.1 디자인 토큰

디자인 토큰은 `src/app/globals.css`의 semantic CSS 변수로 정의하고 Tailwind CSS 4의 `@theme inline`에 연결한다. 컴포넌트에서 hex 색상을 직접 반복하지 않는다.

| 개념 | 용도 |
| --- | --- |
| `background`, `foreground` | 앱 배경과 기본 텍스트 |
| `card`, `card-foreground` | Card와 Dialog 표면 |
| `surface-subtle`, `muted`, `muted-foreground` | 보조 배경과 텍스트 |
| `border`, `input`, `ring` | 경계선, 폼 테두리, 포커스 표시 |
| `primary`, `primary-hover`, `primary-soft` | 대표 행동과 선택 상태 |
| `destructive`, `destructive-hover`, `destructive-soft` | 삭제와 오류 상태 |
| `success`, `warning` | 완료와 주의 상태 |
| `radius` | Control과 Card radius의 기준값 |

향후 Dark Mode는 컴포넌트 class를 바꾸지 않고 semantic CSS 변수 값을 테마 단위로 재정의하는 방식으로 확장한다.

### 2.2 공통 UI 컴포넌트

- `Button`: primary, secondary, outline, ghost, destructive variant와 sm, md, lg 크기
- `Card`: Header, Title, Description, Content, Footer 조합
- `Input`, `Textarea`, `Select`: label, 설명, 오류, disabled 상태
- `Badge`: 상태, 우선순위, 기술을 표현하는 semantic variant
- `Progress`: 0~100 정규화와 progressbar ARIA 정보
- `Dialog`: native dialog 기반 Modal, Escape·포커스 트랩·배경 닫기
- `EmptyState`: icon, 제목, 설명, 선택적 action
- `PageHeader`: 제목, 설명, 선택적 action의 반응형 배치

variant는 TypeScript 문자열 union과 정적 class map으로 제한한다. 페이지는 임의의 색상 조합을 만들기보다 의미에 맞는 variant를 선택한다.

## 3. 전체 레이아웃

### 3.1 Desktop

```text
┌──────────────┬────────────────────────────────────────┐
│              │ Topbar                                 │
│ Sidebar      ├────────────────────────────────────────┤
│              │                                        │
│              │ Page header                            │
│              │ Page content                           │
│              │                                        │
└──────────────┴────────────────────────────────────────┘
```

- 고정 Sidebar와 상단 Topbar를 사용한다.
- 본문은 읽기 쉬운 최대 너비를 가지되 Dashboard 그리드는 넓게 사용할 수 있다.
- Page header에는 제목, 짧은 설명, 대표 행동을 둔다.

### 3.2 Tablet

- Sidebar를 축소형 또는 오버레이 방식으로 전환한다.
- 3~4열 Dashboard 카드가 2열로 줄어든다.
- 표는 필요한 열만 표시하고 나머지는 상세 화면에서 제공한다.

### 3.3 Mobile

- Sidebar는 메뉴 버튼으로 여는 Drawer 또는 하단 핵심 내비게이션으로 전환한다.
- Topbar에는 페이지 제목과 최소 행동만 유지한다.
- 카드와 폼은 1열로 배치한다.
- 표 형태 목록은 카드 목록으로 전환하거나 가로 스크롤을 명시적으로 제공한다.
- 주요 생성 버튼의 터치 영역을 충분히 확보한다.

## 4. Sidebar

### 4.1 구성

- DevLog 로고와 서비스명
- Dashboard
- Projects
- Tasks
- Learning
- Analytics
- 구분선
- Profile 또는 Settings
- 하단 사용자 요약과 로그아웃

Tasks 메뉴는 전체 프로젝트의 Task를 모아 우선순위와 마감일을 확인하는 화면으로 사용한다. Task 생성과 상세 관리는 프로젝트 문맥을 유지할 수 있도록 해당 프로젝트와 연결한다.

### 4.2 상태

- 현재 경로를 텍스트, 아이콘, 배경 차이로 함께 표시한다.
- 축소 상태에서는 아이콘과 tooltip을 제공한다.
- 모바일 Drawer가 열리면 포커스를 내부에 유지하고 Escape로 닫을 수 있어야 한다.

## 5. Topbar

- 모바일 메뉴 버튼
- 현재 페이지 또는 breadcrumb
- 사용자 시간대 기준 오늘 날짜
- 학습 기록 빠른 생성 버튼
- 사용자 메뉴
- 향후 알림 영역은 MVP에서 제외

페이지 대표 생성 버튼과 Topbar 빠른 생성이 중복될 경우 페이지 버튼을 우선하고 Topbar 메뉴는 보조 수단으로 사용한다.

## 6. 공통 UI 패턴

### 6.1 Page header

- 제목
- 설명 또는 현재 범위
- 대표 행동 버튼 하나
- 필요할 경우 보조 행동

### 6.2 상태 표현

- 프로젝트 상태: Badge와 텍스트
- Task 상태: 체크 또는 상태 선택과 텍스트
- 우선순위: 아이콘, 라벨, 색상을 함께 사용
- 진행률: 퍼센트 텍스트와 progress bar

### 6.3 폼

- 라벨과 입력의 연결
- 필수 여부와 도움말
- 필드별 검증 오류
- 저장 중 비활성화와 진행 상태
- 저장 실패 시 입력값 유지
- 취소 또는 이전 화면 이동

### 6.4 피드백

- 목록 로딩에는 Skeleton 사용
- 작은 변경 성공은 간결한 toast 사용 가능
- 중요한 생성·수정 후에는 화면 상태 변화로도 성공을 확인할 수 있어야 한다.
- 삭제는 Dialog에서 대상 이름과 영향을 안내한다.

### 6.5 빈 상태

- 데이터가 없다는 사실
- 왜 필요한지에 대한 짧은 설명
- 첫 데이터를 만드는 행동 버튼

## 7. Dashboard

### 7.1 목적

로그인 후 현재 상태와 다음 행동을 가장 빠르게 파악하는 화면이다.

### 7.2 구조

1. 인사말과 오늘 날짜
2. 요약 카드
   - 진행 중 프로젝트
   - 완료 프로젝트
   - 완료 Task 또는 Task 완료율
   - 연속 학습 일수
3. 프로젝트 진행률
   - 진행 중 프로젝트 최대 4~5개
   - 상태, 기술, 진행률, 다음 마감 Task
4. 이번 주 학습 시간 미니 차트
5. 마감 임박 Task
6. 최근 학습 기록
7. 최근 활동

Day 15부터 Dashboard는 Mock 대신 로그인 사용자의 원본 데이터를 조회한다. 사용자 시간대로 오늘과 주간 경계를 계산한 뒤 프로젝트·Task 요약, 진행 프로젝트 최대 5개, 마감일이 있는 미완료 Task 3개, 최근 학습 기록 3개와 월요일부터 일요일까지의 학습 시간을 표시한다. 연속 학습은 오늘 기록이 없더라도 어제까지 이어졌으면 유지하고, 같은 날짜의 여러 기록은 하루로 계산한다.

Day 16부터 최근 프로젝트 변경, Task 완료, 학습 기록 작성을 시간순으로 합친 최근 활동을 최대 5개 표시한다. 프로젝트와 학습 기록이 모두 없는 신규 사용자에게는 일반 Dashboard 대신 첫 프로젝트 생성과 학습 기록 작성으로 바로 이동할 수 있는 시작 안내를 우선 제공한다. 데이터 조회 중에는 반응형 스켈레톤을 표시하고 예상하지 못한 오류에는 재시도할 수 있는 안전한 오류 화면을 제공한다. 주간 차트에서 학습 시간이 0분인 날은 막대를 표시하지 않으며, 카드 헤더와 목록은 좁은 화면에서 줄바꿈되어 가로 넘침을 방지한다.

### 7.3 빈 상태

- 프로젝트와 학습 기록이 모두 없으면 시작 안내를 우선 표시한다.
- “첫 프로젝트 만들기”와 “오늘 학습 기록하기”를 제공한다.

## 8. Projects

### 8.1 프로젝트 목록

- 페이지 제목과 프로젝트 생성 버튼
- 상태별 요약
- 검색
- 상태 및 기술 스택 필터
- 최신 수정순 등 정렬
- 카드 또는 데스크톱 목록 보기

프로젝트 카드 정보:

- 이름과 상태
- 짧은 설명
- 기간
- 기술 스택
- Task 기반 진행률
- GitHub 연결 여부
- 상세 이동

### 8.2 프로젝트 생성·수정

- 이름
- 설명
- 상태
- 시작일과 종료일
- Next.js, React, TypeScript 등 기본 기술 스택 다중 선택
- GitHub Repository 선택 또는 URL 정보
- 저장 및 취소

프로젝트 생성 시 Task 입력까지 한 화면에 넣지 않는다.
저장에 성공하면 생성된 프로젝트 상세로 이동하고 성공 안내와 첫 Task 추가 행동을 바로 제공한다.
선택한 기술은 프로젝트 저장 transaction 안에서 이름 기준으로 중복을 건너뛰어 생성한 뒤 조회하여 연결한다. 동시 요청에서도 Technology unique 제약 충돌이 발생하지 않아야 한다.

### 8.3 프로젝트 상세

- 이름, 상태, 기간, 편집 메뉴
- 설명과 기술 스택
- 진행률 요약
- Task 영역
- GitHub Repository 요약과 최근 Commit
- 접근 가능한 Repository 선택·변경과 연결 해제 상태
- 최근 업데이트된 Repository를 최대 100개 표시하고 목록이 잘리면 안내
- GitHub API 장애 시 캐시된 Repository 정보와 안전한 Commit 오류 상태
- 위험 영역: 프로젝트 삭제

## 9. Tasks

Task는 프로젝트 상세의 핵심 섹션으로 제공한다.

### 9.1 Task 목록

- 빠른 Task 추가
- 상태 필터
- 우선순위 필터
- 마감 상태 필터
- 정렬: 위치, 마감일, 우선순위
- 모바일 카드 / 데스크톱 행

각 Task에 표시할 정보:

- 완료 체크 또는 상태
- 제목
- 우선순위
- 마감일과 지연 상태
- 편집 메뉴

### 9.2 Task 생성·수정

- 제목
- 설명
- 상태
- 우선순위
- 마감일

완료 토글은 빠르게 수행할 수 있어야 하며 실패하면 이전 상태로 복구하고 오류를 알린다.

### 9.3 삭제

- 일반 Task 삭제는 간단한 확인을 제공한다.
- 삭제 후 프로젝트 진행률이 즉시 갱신되어야 한다.

## 10. Learning

### 10.1 학습 기록 목록

- “오늘 학습 기록” 대표 버튼
- 이번 주 누적 시간
- 날짜 범위 필터
- 카테고리와 기술 필터
- 제목·내용 검색
- 최신 학습일순 기록 목록

학습 기록 카드:

- 날짜
- 제목
- 내용 미리보기
- 학습 시간
- 카테고리
- 기술 스택
- 수정·삭제 메뉴

최신 학습일과 생성 시각의 내림차순으로 사용자 소유 기록만 조회한다. 목록은 페이지당 6개의 반응형 카드로 제공하며 긴 제목과 내용은 줄바꿈과 3줄 미리보기로 제한한다. 제목·내용 검색, 시작일·종료일, 카테고리와 기술 조건은 GET search parameter로 유지하고 페이지 이동에도 보존한다. 카드에서 `/learning/[learningLogId]` 상세 화면으로 이동해 전체 내용, 날짜, 시간, 카테고리와 기술 스택을 확인한다.

### 10.2 작성·수정 폼

- 학습 날짜
- 제목
- 학습 내용
- 학습 시간: 시간과 분 입력 또는 분 입력
- 카테고리
- 기술 스택 다중 선택

입력 과정이 길어지지 않게 한 페이지 또는 넓은 Dialog로 제공한다. 모바일에서는 전체 화면에 가까운 폼을 사용한다.

`/learning/new` 전체 페이지 폼으로 구현한다. 기본 학습일은 사용자의 IANA 시간대를 기준으로 정하고, 저장 후 `/learning`에서 성공 상태와 최신 목록을 보여 준다.

수정은 `/learning/[learningLogId]/edit`에서 같은 폼을 재사용하며 기술 연결을 트랜잭션 안에서 교체한다. 삭제는 상세 화면의 위험 영역에서 확인 Dialog를 거친다. 수정·삭제 Server Action은 세션 사용자와 기록 소유권을 함께 검증한다.

## 11. Analytics

### 11.1 상단 컨트롤

- 기간 선택: 이번 주, 이번 달, 사용자 지정
- 선택한 기간 설명

### 11.2 지표 및 차트

- 총 학습 시간
- 평균 일일 학습 시간
- 연속 학습 일수
- Task 완료율
- 일별·주별 학습 시간 Bar 또는 Area chart
- 최근 365일 학습 캘린더 히트맵
- 기술별 학습 비율 Pie 또는 Bar chart
- 프로젝트별 진행률 목록

### 11.3 접근성

- 모든 차트에 제목과 요약 문장을 제공한다.
- tooltip에서만 확인 가능한 핵심 정보가 없도록 한다.
- 차트 아래에 표 또는 텍스트 요약을 제공한다.
- 색상 구분 외에도 label과 pattern/순서를 활용한다.

데이터가 적을 때 억지로 차트를 채우지 않고 기록을 추가하도록 안내한다.

Day 17 집계 계층은 사용자 시간대를 기준으로 월요일부터 일요일까지의 이번 주와 달력 기준 이번 달을 계산한다. 기록이 없는 날짜는 0분으로 채우고, Task 완료율과 프로젝트 진행률은 현재 `DONE` 상태를 기준으로 계산한다. 선택 기간의 기술별 학습 시간은 하나의 학습 기록에 여러 기술이 연결된 경우 기록 시간을 기술 수로 균등 배분하며, 기술이 없는 기록은 기술 비율에서 제외한다.

Day 18부터 이번 주, 이번 달과 최대 366일의 사용자 지정 기간을 URL 검색 조건으로 선택한다. 62일 이하 기간은 일별 막대, 더 긴 기간은 7일 단위 막대로 표시한다. 기술 비율은 도넛 차트와 화면 폭에 따라 아래 또는 옆으로 배치되는 별도 범례를 함께 제공한다. 학습 차트에는 총합·최대 학습 구간 설명과 펼칠 수 있는 데이터 표를 제공해 차트를 보지 못해도 같은 정보를 확인할 수 있다. 학습 또는 기술 데이터와 프로젝트가 없을 때는 각각 다음 행동을 안내한다.

Day 32부터 Analytics에 사용자 시간대 기준 최근 365일의 학습 캘린더를 표시한다. 날짜별 총 학습 시간을 5단계 강도로 구분하며 색상 범례와 스크린 리더용 날짜·시간 설명을 함께 제공한다. 학습 기록이 있는 날짜를 선택하면 해당 날짜로 필터링된 Learning 목록으로 이동하고, 좁은 화면에서는 캘린더 영역만 가로로 스크롤한다.

Dialog와 모바일 메뉴는 열린 직후 포커스 이동, Tab 순환, Escape 닫기와 실행 요소로의 포커스 복귀를 검증한다. Dashboard, Projects, Tasks, Learning, Analytics, Profile은 360×800, 768×1024, 1440×900 viewport에서 의도하지 않은 문서 가로 스크롤이 없는지 확인한다.
